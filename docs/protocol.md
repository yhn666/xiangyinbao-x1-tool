# 相印宝 X1 打印协议笔记

这份笔记记录在 Windows 上直连得力相印宝 X1（内部为 HPRT 方案）时逆向出来的协议细节，
供后来者参考。没有版权代码，只有协议描述和实测结论。

> 适用机型：得力 `X1 / X1B` 相印宝（BLE 名 `XiangYinBao_X1_xxxx`）。
> 其它 X3/X4/X7 走的是另一套指令集（AY SDK / HPRT ESC-POS 扩展），本笔记不覆盖。

## 1. 物理与传输层

| 项目 | 值 |
|---|---|
| 打印头 | 384 点 / 行（48mm）@ 203dpi |
| 走纸 | 1 点行 = 1/203 英寸，8 点 ≈ 1mm |
| 走纸命令单位 | 1 "行" = 24 点 = 3mm |
| 打印头 → 撕纸口 | 实测约 33mm |
| BLE 服务 | `0000ff00-…`，写 `ff02`，通知 `ff01`（`ff03` 是状态广播） |
| 经典蓝牙 | SPP / RFCOMM `00001101-…`，官方 App 用的就是这条 |

两条通道跑同一套字节流协议：官方 App 走 SPP；BLE 需要自己分包 + 控速（见第 5 节）。

## 2. 帧格式

```
0x02 | cmd | pkg | len(LE16) | payload | crc32(LE32) | 0x03
```

- `pkg`：包序号，1..127 循环（握手那一帧固定 0）。
- `len`：payload 字节数（小端 16 位）。
- `crc32`：payload 的标准 CRC-32，**初值为当前密钥**，小端 32 位。
  Python 里等价于 `zlib.crc32(payload, key)`（注意不要再手动 xor 0xFFFFFFFF）。

## 3. 密钥握手

连接后先发：

| 字段 | 值 |
|---|---|
| cmd | `0x18` |
| pkg | `0` |
| payload | `le32(new_key ^ 0x35769521)` |
| CRC | 用默认密钥 `0x35769521` 计算 |

设备回 `cmd=0x18`、payload = `0x00` 表示成功；之后所有帧的 CRC 都用 `new_key`。
回 `0x01` 表示让它重发，其它值视为失败。

## 4. 常用指令

| 用途 | cmd | payload |
|---|---|---|
| 打印位图数据 | `0x00` | 见第 6 节 |
| 读状态 | `0x0C` | `0x00`，回 1 字节位标志 |
| 设浓度 | `0x19` | 1 字节，官方三档 55 / 75 / 95 |
| 走纸 | `0x1A` | `le16(行数 × 24)` |
| 设走纸头位置 | `0x21` | `le16(行数 × 24)` |
| 自动关机 | `0x1F` | `le16(秒)`（只读时用 `0x1F` 查询） |
| 自检 | `0x1B` | `0x00` |
| 固件升级 | `0x02` | 1024 字节分块，逐包等 ACK |

状态字节（`0x0C` 的返回）：

| bit | 含义 |
|---|---|
| 0x01 | 缺纸 |
| 0x02 | 打印头过热 |
| 0x04 | 电量低 |
| 0x08 | 开盖 |
| 0x10 | 电池异常 |

## 5. BLE 传输的坑

Windows（WinRT/bleak）上实测：

| 方式 | 吞吐 | 结果 |
|---|---|---|
| 有应答写入，20 字节 | ≈ 1 KB/s | 跟不上打印头，出纸一顿一顿 |
| 无应答写入，猛发 | ≈ 35 KB/s | 模块串口缓冲溢出，整帧被丢，打印没反应 |
| 无应答，每 240 字节停 20ms | ≈ 11 KB/s | 稳定、连续 |

所以 BLE 兜底路径用「突发 + 停顿」的节奏。能走 SPP 时优先 SPP（虚拟串口按 1024 字节分块写，
整条字节流连续灌进去即可，和官方 App 一致）。

## 6. 位图数据

- 1bpp，行序自上而下，MSB 在前，**1 = 黑点**（写反了会得到黑底白字）。
- 每包最多 30 行（48×30 = 1440 字节），一页拆成多个 `cmd=0x00` 包依次发送，包序号递增。
- 二值化：官方 App 有三种
  - `0` Otsu 自适应阈值（"纯文字/增强文字"）
  - `1` Floyd–Steinberg 误差扩散（"图文/图片"）
  - `2` Bayer 8×8 有序抖动

## 7. 纸张与浓度

协议里没有"纸张类型"指令。官方 App 的纸张选项只做两件事：

1. 按纸张类型从服务端拉一套浓度档位（默认淡 55 / 中 75 / 深 95）；
2. 拦掉"4 寸纸配 2 寸机型"这类非法组合。

不干胶与普通热敏纸的差别在物理（放置方向相反）和吃热程度：同浓度不干胶更深，
实测不干胶 75 ≈ 普通纸 95。

## 8. 走纸与纸尾

官方 App 打完固定发 `setPrintFeedLine(10)`，即 10×24 = 240 点 ≈ 30mm。
由于打印头到撕口约 33mm，纸面只剩约 3mm 空白——官方默认就是这么短。
